# Governance — D'Jaemo Jamur Krispi

This folder is the permanent governance system for the project. Every engineer (human or AI) MUST read the relevant document before starting work.

---

## When to Read Each Document

| Document | Read When |
|----------|-----------|
| `01_TECH_LEAD_CONTEXT.md` | **Before ANY work.** Contains the permanent architectural decisions, tech stack, patterns, and philosophy. Never modify without Tech Lead approval. |
| `02_ENGINEERING_CONSTITUTION.md` | **Before ANY work.** Contains binding rules: what engineers MUST and MUST NOT do. Violations require Tech Lead approval. |
| `03_PROJECT_WORKFLOW.md` | **Before starting your first sprint.** Explains how work flows from Product Owner → ChatGPT → OpenCode → Review → QA → Merge. |
| `04_DEFINITION_OF_DONE.md` | **Before submitting ANY PR.** Every sprint and PR must pass these quality gates. |
| `05_PROJECT_ROADMAP.md` | **When planning or prioritizing.** Shows completed, current, next, and future sprints. |
| `06_CURRENT_SPRINT.md` | **At the start of every sprint.** Updated each sprint with scope, status, blockers, and next actions. |

---

## Principles

1. **Read first, write second** — always read existing docs before creating new ones
2. **Don't duplicate** — reuse existing information; write TODO if it can't be verified
3. **Don't invent** — all information must be verifiable from existing documentation or source code
4. **Governance is permanent** — changes require Tech Lead approval and must update this folder
